# TP 01 — CI observable et bloquante

Adaptation du [TP Rental](https://github.com/charroux/rental/blob/main/course/labs/tp01.qmd)
sur GeoBall, branche `tp/01-ci`. Le point de départ est notre application existante,
pas le tag Rental qui contient un autre projet. Les deux services étant en Python,
Ruff remplace la partie Checkstyle/Java.

## Contrôles

Chaque service a son workflow : tests et qualité en parallèle, puis image Docker
avec `needs: [tests, quality]`. Gitleaks s'exécute dans un troisième workflow.
Les sept noms à utiliser pour les contrôles requis sont :

- `Catalogue tests`
- `Catalogue quality`
- `Catalogue Docker image`
- `Quiz tests`
- `Quiz quality`
- `Quiz Docker image`
- `Secret detection`

Tous les workflows ont des permissions `contents: read`, des délais explicites et
une annulation des exécutions devenues obsolètes. Les dépendances pip sont mises
en cache. Aucun filtre `paths` sur les PR : un contrôle requis doit toujours être
créé, même si le changement ne touche qu'un README.

Les PR construisent les images sans les publier. Après un push sur `main`, les
images sont publiées sur Docker Hub sous un tag `sha-<commit>`. Le déploiement
Minikube n'est pas modifié automatiquement par cette CI.

JUnit, JSON Ruff et résultat du formatage sont téléversés avec `if: always()`,
conservés sept jours. Gitleaks parcourt tout l'historique avec un rapport expurgé.
Les rapports locaux sont dans `reports/`, hors Git.

## Commandes locales

Installer les dépendances de développement des deux services, puis :

```powershell
python scripts/course.py verify
```

Commandes séparées : `test`, `lint`, `test-catalog`, `test-quiz`,
`lint-catalog`, `lint-quiz`. Chaque service est testé dans un processus séparé
pour isoler les deux packages `app`. `verify` s'arrête au premier échec, avec
le code 1. Il ne construit pas les images et ne lance pas Gitleaks.

Sur ce PC, une bibliothèque native est bloquée par Windows. Vérification effectuée
avec Python 3.13 dans Docker. Alternative depuis PowerShell à la racine :

```powershell
$source = (Get-Location).Path
docker run --rm --mount "type=bind,source=$source,target=/workspace" --workdir /workspace gabriel0langlois/geoball-quiz:0.2 sh -c 'pip install -r services/catalog/requirements-dev.txt -r services/quiz/requirements-dev.txt && python scripts/course.py verify'
```

Vérifié localement : 27 tests, Ruff E/F/I et formatage réussis.
Dans une copie temporaire, une assertion fausse produit un rapport JUnit en échec
et arrête `verify` avant le quiz. Un import inutilisé produit un rapport F401 et
un code 1. Ces essais ne remplacent pas l'expérience sur PR demandée par le TP.

## À terminer sur GitHub

1. Ouvrir une PR en brouillon de `tp/01-ci` vers `main`.
2. Observer les sept contrôles, puis télécharger les rapports.
3. Faire l'expérience d'échec sur cette PR : un commit d'assertion fausse,
   observer le job et son rapport, puis un commit de correction. Noter le lien
   de l'exécution, la ligne d'erreur et le temps de retour.
4. Pour l'exercice Gitleaks, utiliser uniquement la valeur factice donnée par le
   professeur, sur une branche jetable. Pas de vrai jeton.
5. Avant fusion : créer un jeton Docker Hub lecture/écriture et le fournir dans
   GitHub > Settings > Secrets and variables > Actions > `DOCKERHUB_TOKEN`.
   Ne pas le mettre dans un fichier ou dans la PR.
6. Après validation du professeur : protéger `main`, exiger une PR et les sept
   contrôles ci-dessus. Tester le blocage d'une PR rouge, puis le passage au vert.
   Ne pas autoriser de contournement si l'on veut vérifier le blocage réel.

Supprimer une ligne contenant un secret ne l'efface pas de l'historique.
Un vrai secret exposé doit être révoqué ; une réécriture d'historique est une
opération distincte, à coordonner, qui ne remplace pas la révocation.

Les signatures, SBOM, attestations et scans d'images du TP 02 ne sont pas ajoutés.
